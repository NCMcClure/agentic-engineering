# agentic-engineering: a Claude Code plugin marketplace

One plugin, `agentcraft`. Each of its thirteen areas is a fix for a problem
that keeps turning up when engineering with agents, and `start-here` is the
one skill a person types to find the right one. The catalog lists that one
plugin and nothing else. Nothing here runs in production; it runs in the agents, so a mistake ships to every
session that has the plugin installed.

Read the rules below before editing anything under `plugins/` or the catalog.
They are the maintenance contract, and they name what `scripts/validate.mjs`
enforces.

@.agents/rules/dev-rules.md

## Layout

- `.agents/rules/` - this repo's own rules. `dev-rules.md` is the contract
  imported above.
- `.agents/picture-this.json`, `.agents/picture-this/figures/` - the figures
  this repo draws of its own areas: each one's source (a React component
  and the model it draws) and the picture-this kit beside them. Their stills
  go into the area they illustrate; the plugin ships no source. A model's
  sources name its area's files, and `pt still <figure> --gif --dark --out
  plugins/agentcraft/skills/<area>/assets/figures` retakes what that area's
  README shows.
- `.claude-plugin/marketplace.json` - the catalog: one entry, `agentcraft`.
  Never a `version` key.
- `plugins/` - `agentcraft/`, the one plugin, and nothing beside it. Its
  `AGENTS.md` says what each area is for. Descend to change what an agent
  does.
- `scripts/` - repo tooling, never shipped: `validate.mjs` (the structural
  gate), `gen-guide.mjs` (what `npm run guide` writes), `install.mjs` and
  `refresh.mjs` (the local dev loop; they install `agentcraft`), `lib.mjs`, and `test-hooks/` (the unit and live lanes; its README
  has the detail).
- `docs/assets/` - the pictures only the root README shows: two figures of
  the plugin as a whole (`goal-to-main`, how a goal moves through the areas,
  and `routes-behind-names`, whose route counts a unit test holds to the
  doors: `pt still <figure> --gif --dark --out docs/assets` retakes one), the banner
  (`banner.gif`, `banner.dark.gif`) and the picture-this worked example. The
  banner is the `banner` figure, with its avatar and fonts beside it:
  `pt still banner --gif --dark --width 1600 --fps 24 --out docs/assets`
  retakes it.
- `docs/known-limits.md` - host behaviors the marketplace leans on, each with
  the Claude Code build it was measured on and how. Read it before relying on
  how the host installs, lists, or refuses something.
- `docs/plugins.md` - the plugin, its version, its areas and their routes,
  generated by `npm run guide`. Never edited by hand.
- `.github/workflows/validate.yml` - CI: the gate, the unit lane on three
  operating systems, and the tag check.
- `package.json` - the npm script names. No dependencies, ever.
- `README.md` - for a person: what this is, how to install, a section per area.
- `CONTRIBUTING.md` - what to run before a commit, the dev loop, releasing.
- `AGENTS.md` / `CLAUDE.md` - this hub and its tracked link.

## Before every commit

```bash
npm run validate   # the structural gate CI runs
npm test           # the unit lane CI runs
```

Run `npm run test:live` too when a change alters what an agent sees: a hook, an
area's description, a route's cue, a rule a hook injects.
