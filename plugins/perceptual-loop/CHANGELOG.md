# Changelog

- **1.0.0**: Node 22 throughout, no `uv`. **Breaking:** the per-command Python scripts are one CLI, `node scripts/pl.mjs <command>` (`evidence_lint.py` is `pl.mjs lint`, `review_page.py` is `pl.mjs review`, `init.py new-shot` is `pl.mjs new-shot`), with its own PNG, JPEG, WAV and DSP code and `ffmpeg` as the one external tool; the numbers match the Python ones (frame metrics within 0.00002, region metrics within 0.00005, edge scores and calibration exactly, sound to the printed digit, onsets within 2 ms), so an accepted baseline keeps gating. State moves from `.perceptual-loop/` to `.agents/perceptual/`: the first session renames the folder, rewrites nothing inside it, and names the config keys still spelling the old path, which the CLI keeps reading meanwhile (`PL_DIR` replaces `PERCEPTUAL_LOOP_DIR`, still read). A render command is started as a program with its arguments, never through a shell: a string is split into words, and one that needs a shell is refused with the fix (a script, or an array naming the shell). Skills renamed: `build-harness` is `shot-harness`, `iterate` is `iterate-shots`; `orchestrate-agents` is gone and its brief is `references/agent-brief.md`. The guard is Node, reads a command as a shell does, and now sees a render inside `bash -c` or `powershell -Command` as well as behind `aw lock run ... --`; `baseline update --all` is refused in favour of `--all-shots-of-run`. New: four doctrine lines kept in context where the repo has opted in (session start, after a compaction, working subagents, never the blind critic), a session line saying a harness exists, a stricter blind critique (pictures copied to neutral names by `pl.mjs blind`, the key kept out of every prompt, a skeptic per finding), `sheet triptych`, `video`/`sweep`/`flow` with an unknown share for what flow cannot measure, and `pl.mjs timing`. `semantic` and `keypoints` stay optional Python extras behind `pl.mjs semantic` and `pl.mjs keypoints`; every other script, the `--self-test` flags and `--jobs` are gone.
- 0.2.0 — Locks and orchestration defer to the agent-works plugin. **Breaking:** `scripts/lock.py` (locks, the queue, the notes board) and the hook's `locks` rule are gone, so without agent-works nothing enforces one agent at a time on a scarce application; `locks` in `.perceptual-loop/config.json` is ignored (declare the application as a resource in agent-works instead; `PL_AGENT` is still honoured there as an alias). The budget rule now reads through `aw lock run … --` and `aw lease … --`. `orchestrate-agents` keeps the perceptual half (success files, proving shots, proportionate verification, opening the pictures, the owner's queue) and its brief template becomes an addendum to agent-works' common brief; load checks before a timing use `aw sys --quiet-for timing`; `probe-the-source` and `judge-and-queue` point at agent-works for the project's memory and for rulings that bind beyond a look.
- 0.1.0 — First release: ten skills, the vision-critic agent, the critique workflow, the script set, the guard hook.
