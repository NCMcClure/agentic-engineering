# Changelog

- **2.1.0**: The context lens names the area. Where a plugin's skills hold `routes/`, a hook is attributed to the area its command runs from, a listing entry to the area it names, and each `Critical, from <area>:` block inside one hook's output to the area in its heading; the report and the page print the area in place of the plugin, whose name is then the same for everything. `report --json` also carries each listing entry's size and whether it kept its description, every call on the Skill tool, and every read of a skill's or a route's file, with whether it went through. A session of plugins with no areas reads exactly as before.
- **2.0.0**: Rubric 2. The scanner reads areas (a skill that holds `routes/`) and their routes, allows `user-invocable` in frontmatter, and the rubric stops rewarding a hidden skill the plugin sends an agent to: the host refuses that call. Three mechanical checks are new and apply only to a plugin with areas, routes, or critical lines: SQ9 (an area names and ships every route), AN6 (a route names its directories from its own file), and CF6 (critical lines within 7,500 characters). SQ8 now also fails a description that holds a colon and a space unquoted, CS7 a hook script that ends the process early, and CF4 an area body over 8,000 characters. A plain plugin gets the same composite for the same grades; SQ8 and CS7 can move, and a scan, a score, and a scorecard now say which rubric graded them. The rules and fixes for the eight house checks moved to `core/references/mechanical-checks.md`. `improve-plugin` and `create-plugin` no longer send an agent to `evaluate-plugin`, which only a person starts.
- **1.0.2**: The scorecard and the context-lens page take the marketplace house style, in light and dark by `prefers-color-scheme`: neutral faces and hairlines, one orange accent, mono capitals for labels, tabular mono numbers, no traffic-light colours. The scorecard template carries its own stylesheet and no longer loads Tailwind from a CDN, so it opens styled offline (the component map still needs Mermaid). Its fill maps now name classes and tokens the stylesheet defines (`v-adopt`, `sev-minor`, `seg-1`, `cap-ok`, `var(--ink)`) where they named Tailwind utilities, and the maps for the gauge, the verdict chip, the dimension bar and the kind tag are written beside their blocks: the grade is ink, a rework or avoid verdict takes the accent, and the lowest-scoring dimension's bar is the one in orange. In context-lens a plugin's dot is a hue given in footprint order (ink tones, then rings, past five) where it was hashed from the name, a selected session or lens carries the accent, and what a compaction dropped is a dashed chip on a quieter row. The README shows both pages. No placeholder, id, script contract or report field changed.
- **1.0.1**: The README shows how a plugin becomes one score: `assets/figures/ledger-to-verdict`, a looping GIF in light and dark. Nothing the plugin runs changed.
- **1.0.0**: Node 22 throughout, no Python. The scanner is `core/scripts/plugin-scan.mjs` and the scaffolder is `skills/create-plugin/scripts/plugin-scaffold.mjs` (were `plugin_scan.py` and `plugin_scaffold.py`): the same arguments behind `node`, the same JSON, and the same arithmetic to the digit for the same grades. Scores move for a different reason, because the rubric now agrees with what a marketplace gate enforces. MH3 reads `CHANGELOG.md` (4 when its first bullet opens with the manifest version and the README carries no `## Changelog` section, 2 when one of those fails, 0 with no file) where it used to read a README changelog, and `CHANGELOG.md` is no longer reported as an orphan. Four mechanical checks are new: SQ8 (SKILL.md frontmatter of `name`, `description`, `disable-model-invocation`, `argument-hint` and nothing else), CS7 (a hook command that runs Node sits behind the guard, loud and with a `statusMessage` at `SessionStart`), WQ7 (a skill that calls `Workflow()` names a subagent fallback), and MH5 (shipped scripts run on Node, or the file carries a `debt:` comment). The scan counts `.mjs`, `.cjs` and `.js` files as scripts (it saw only `.py` and `.sh`), lists browser `.js` under `assets/` separately, prints forward-slash paths on every platform, and reports `changelog`, `readme.changelog_section`, each hook's guard, and each skill's `extra_fields` in place of the README changelog fields. The scaffolder now writes `CHANGELOG.md` and no README changelog, a Node script stub at `scripts/<skill>.mjs` (was `scripts/<skill_name>.py`), a section in each SKILL.md for every sibling file it creates, and valid JSON when a description holds a quote. New skill `/plugin-workbench:refresh-marketplace`: validate a marketplace checkout and reinstall its plugins from the working tree. Both autonomous modes say how to run the same phases with subagents where a session has no Workflow tool.
- **0.2.0**: new `context-lens` skill. It reads a Claude Code session transcript back and shows what entered the agent's context, when, and from which plugin: each hook's output and who saw it (the model, the person, or nobody), the skill listing per plugin, the API's token count per request, and what each compaction kept or lost. A terminal report, or a local page with the per-request chart.
- **0.1.1**: the create/evaluate workflows and their skill docs resolve `python3` or `python` instead of hardcoding `python3`, so the scan/scaffold/score commands run where only `python` is installed (e.g. Windows/Git-Bash).
- **0.1.0**: initial release: the six-dimension measurement core (rubric,
  deterministic scanner/scorer, HTML scorecard), create-plugin with
  deterministic scaffolding and an autonomous authoring workflow,
  evaluate-plugin with adversarially-verified autonomous evaluation, and
  improve-plugin's delta-ranked fix loop.
