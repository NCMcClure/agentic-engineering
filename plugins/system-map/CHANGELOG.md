# Changelog

- **0.2.0**: Renamed from `marvelous-miro` to `system-map`, and the README, the descriptions and the catalog entry lead with the map: the annotations, the committed map, the check against the import graph and the sweep first, Miro as the place the map is drawn. An installed `marvelous-miro` does not update in place: uninstall it and install `system-map`. Slash commands are now `/system-map:...`, the session lines and the checker's messages name them, and the browser server is listed as `plugin:system-map:miro-browser`, so a permission rule that names its tools needs the new prefix. No script changes what it does, with one addition: the live check's Chrome profile is `~/.cache/system-map/chrome-profile`, and a profile made under `~/.cache/marvelous-miro/` stays the one in use, so nobody signs in to Miro twice. The path overrides are `SYSTEM_MAP_CHROME` and `SYSTEM_MAP_DESKTOP_CONFIG`. Skill names, `miro.config.mjs`, the `miro/` folder, `.agents/system-map.json` and the `miro-browser` server keep their names, so a repo that adopted the map needs no change.
- **0.1.2**: The boards wear the marketplace's house style. Every palette name stays and its values change: `gray` is a white panel with a quiet outline, `teal` the heavier neutral (a grey face with an ink outline, since the house has no teal), `blue`, `green`, `purple` and `yellow` the house hues over a pale tint of themselves, `orange` the accent; titles, body lines and connectors take the house inks, and a frame is the house page color (`#f5f5f3`) where it was white. On a system map a system outside the repo is a neutral card with a dashed outline where it was orange, so the accent is left for the one thing a frame is about. The next build finds every item it recolored changed and writes it into the update. `references/generator-api.md` says when to use a color, and the README shows a frame. No lint rule read a color value, and none changed.
- **0.1.1**: The README shows how a Miro frame goes from code to the board and back: `assets/figures/repo-and-board`, a looping GIF in light and dark. Nothing the plugin runs changed.
- **0.1.0**: initial release. A system map extracted from `@system` annotations and checked against the import graph (`scripts/system-map.mjs`, skills `diagrams-init` and `diagrams-sync`, a whole-repo sweep), and Miro boards drawn from code with a legibility lint before publishing, a live check after, and layout pulled back from the board (skills `miro-board` and `browser-setup`).
