# Changelog

- **1.0.0**: Node 22 throughout, no Python. The scanner is `core/scripts/plugin-scan.mjs` and the scaffolder is `skills/create-plugin/scripts/plugin-scaffold.mjs` (were `plugin_scan.py` and `plugin_scaffold.py`): the same arguments behind `node`, the same JSON, and the same arithmetic to the digit for the same grades. Scores move for a different reason, because the rubric now agrees with what a marketplace gate enforces. MH3 reads `CHANGELOG.md` (4 when its first bullet opens with the manifest version and the README carries no `## Changelog` section, 2 when one of those fails, 0 with no file) where it used to read a README changelog, and `CHANGELOG.md` is no longer reported as an orphan. Four mechanical checks are new: SQ8 (SKILL.md frontmatter of `name`, `description`, `disable-model-invocation`, `argument-hint` and nothing else), CS7 (a hook command that runs Node sits behind the guard, loud and with a `statusMessage` at `SessionStart`), WQ7 (a skill that calls `Workflow()` names a subagent fallback), and MH5 (shipped scripts run on Node, or the file carries a `debt:` comment). The scan counts `.mjs`, `.cjs` and `.js` files as scripts (it saw only `.py` and `.sh`), lists browser `.js` under `assets/` separately, prints forward-slash paths on every platform, and reports `changelog`, `readme.changelog_section`, each hook's guard, and each skill's `extra_fields` in place of the README changelog fields. The scaffolder now writes `CHANGELOG.md` and no README changelog, a Node script stub at `scripts/<skill>.mjs` (was `scripts/<skill_name>.py`), a section in each SKILL.md for every sibling file it creates, and valid JSON when a description holds a quote. New skill `/plugin-workbench:refresh-marketplace`: validate a marketplace checkout and reinstall its plugins from the working tree. Both autonomous modes say how to run the same phases with subagents where a session has no Workflow tool.
- **0.2.0**: new `context-lens` skill. It reads a Claude Code session transcript back and shows what entered the agent's context, when, and from which plugin: each hook's output and who saw it (the model, the person, or nobody), the skill listing per plugin, the API's token count per request, and what each compaction kept or lost. A terminal report, or a local page with the per-request chart.
- **0.1.1**: the create/evaluate workflows and their skill docs resolve `python3` or `python` instead of hardcoding `python3`, so the scan/scaffold/score commands run where only `python` is installed (e.g. Windows/Git-Bash).
- **0.1.0**: initial release: the six-dimension measurement core (rubric,
  deterministic scanner/scorer, HTML scorecard), create-plugin with
  deterministic scaffolding and an autonomous authoring workflow,
  evaluate-plugin with adversarially-verified autonomous evaluation, and
  improve-plugin's delta-ranked fix loop.
