# One home per kind of fact

A project's agent files rot in two ways: one file grows until nobody reads it, and one fact gets written in four
places that then disagree. Both have the same cure. Every kind of fact has **one home**, each home has a **budget**,
and one command checks them all: `aw doctor`. Everything agent-facing lives under `.agents/`, beside the root
`AGENTS.md` and its hubs.

## The homes

| Fact | Its one home | Budget (default) | Checked by |
|---|---|---|---|
| Orientation: what is where | root `AGENTS.md`, and a hub `AGENTS.md` in every non-leaf code directory | root 200 lines, hub 40 | `aw hubs` |
| Which plugins the project works with, and when to open each skill | root `AGENTS.md` § Agent plugins, written by `aw setup --apply` from `plugins` in the config | inside the root's 200 | `aw doctor` (`ROOT_PLUGINS`) |
| Project rules | root `AGENTS.md` § Rules: five lines each at most, with a link to the decision or memory that says why | inside the root's 200 | `aw dup` |
| How the homes work (this page, in brief) | `.agents/README.md`, generated by `aw setup --apply` and stamped with the plugin's version | 120 lines | `aw doctor` (`CONTRACT_MISSING`, `CONTRACT_STALE`) |
| Why, measurements, lessons | a memory: `.agents/memory/<folder>/<date>-<slug>.md` | 400 lines a file, 12 files a folder | `aw memory lint` |
| Memory indexes | `INDEX.md` at every level, generated from each memory's `description` (hand-written ones are kept until adopted: `aw memory index --adopt`) | 160 characters a line | `aw memory index --check` |
| Status | the one memory of type `status` (`project-status`): Goal, Current focus, Known issues as card links | 120 lines | `aw memory lint` (`STATUS_*`) |
| What is done | the git log and the closed cards | derived, never written | `aw status` prints it |
| Decisions | `.agents/decisions/NNNN-slug.md`, with a generated `README.md` index | 150 lines; one amendment | `aw decisions lint` |
| Words | the glossary `.agents/CONTEXT.md` | 300 characters a row | `aw decisions lint` (`GLOSSARY_*`) |
| Agent-facing contracts: protocols, formats, how to extend | `.agents/contracts/` | none | `aw links` |
| Plans and specs | `.agents/plan/` (the but-first-planning plugin's workspace) | its own | its own verifiers |
| Tasks and their status | kanban cards in the main working tree's `.agents/kanban/`, shared by every worktree | none | `aw kanban lint` |
| Checks still owed | cards of kind `gate`: what, for which pull request or card, what running it needs | none | `aw kanban lint` (`GATE_OWED_OLD`) |
| Briefs for a round of agents | `.agents/briefs/common.md` and `.agents/briefs/rounds/<date>-<slug>.md`, tracked by git | 120 and 80 lines | `aw doctor` (`BRIEF_SIZE`, `BRIEF_UNTRACKED`, `BRIEF_STRAY`) |
| Reports | the agent's final message, the pull request's body, the card | never a file | by reading |
| Files for one tool | a `CLAUDE.md` twin beside every `AGENTS.md`, one line: `@AGENTS.md` | one line | `aw twins --check` |
| The plugin's settings | `.agents/agent-works.json` (`guard-config.md` documents it) | none | `aw doctor` (`CONFIG_INVALID`) |
| User-facing documentation | `./docs`, and nothing else lives there | none | `aw doctor` (`DOCS_AGENT_FILE`) |
| What holds on any project of this machine | shared learnings in the machine's store, through `aw learn` (`coordination.md`) | none | by reading |

The budgets are `budgets.*` in `.agents/agent-works.json`. A budget is where a file stops being read; raise one
only with a reason you would write down. One file that is over for a good reason (a reference memory that is the
approved plan, kept as written) is not a reason to raise the budget for all: the owner accepts that one finding in
`accept` of the config, with its why (`guard-config.md`), and `aw doctor` stops counting it.

## What never goes where

- **No status in `AGENTS.md`.** Every session loads the root file. What is in progress, what just landed and what
  is broken this week go to the status memory and the board (`ROOT_STATUS_PROSE`).
- **No Done list in the status memory.** Finished work is the git log and the closed cards; `aw status` prints
  both. A changelog in the status file is how it reaches two thousand lines (`STATUS_DONE_SECTION`, `STATUS_SIZE`).
- **No reports in the repository.** A report is read once. It is the final message, the pull request's body or the
  card; what it established that must last becomes a memory, and what it leaves open becomes a card.
- **Nothing agent-facing under `./docs`.** That folder is for the people who use the project. Decision records, the
  glossary, protocol and format pages written for agents, briefs and memory all live under `.agents/`
  (`DOCS_AGENT_FILE` names each stray and the `git mv` that moves it).
- **No rule in two places.** A rule is stated once, in the root `AGENTS.md`, and linked from everywhere else: a
  brief, a hub, a memory and a guard message point at it. `aw dup` finds a run of fourteen words that two rule
  files share (`DUP_RULE`); keep one copy and make the other a link.
- **No why in a rule.** The rule is five lines; the reasoning, the measurement and the incident live in the
  decision or memory it links to.
- **No rules in a scratch file.** A brief that git does not track loses its rules with the next clean-up
  (`BRIEF_UNTRACKED`), and a brief or hand-over written into a scratch or run-output folder is found by no agent
  (`BRIEF_STRAY`: `aw doctor` looks for the names of `briefs.stray` outside the briefs folder, in git-ignored
  folders too). What every round needs is in `.agents/briefs/common.md`; what binds beyond the round moves into
  `AGENTS.md`.
- **No tasks in prose.** A TODO list in a memory, a "Next" section in the status file and a note that says "still
  to do" are tasks without a status. A task is a card (`TASKS_TWO_HOMES` when two places hold them).
- **No hand edits of generated files:** `.agents/README.md`, every generated memory `INDEX.md`, the decisions `README.md`,
  the `CLAUDE.md` twins. Change the source and run the command that writes them.

## Which home, when you hold a fact

1. Is it about the machine, a tool or an engine, true in any repository? A shared learning: `aw learn add`.
2. Is it work to do, or a check to run later? A card: `aw kanban add`, `aw kanban owe`.
3. Is it a choice that is hard to reverse, surprising without context, or a real trade-off? A decision record:
   `aw decisions new`.
4. Is it the meaning of a word the project uses? A glossary row.
5. Is it a rule every agent must follow here? One entry under Rules in the root `AGENTS.md`, linking to its why.
6. Is it what a directory holds? A line in that directory's parent hub.
7. Is it a measurement, a lesson that cost time, or the reason behind something? A memory: `aw memory new`.
8. Is it what was done? Nothing to write: commit it, close the card.

## The check

`aw doctor` runs every check at once and exits 0 (clean), 1 (warnings) or 2 (critical). Only three findings are
critical, so an old repository gets a report rather than a wall: source files beside a hub (`HUB_ISOLATION`), a
config that does not parse (`CONFIG_INVALID`), and a status memory over three times its budget (`STATUS_SIZE`).
`aw doctor --baseline` records today's sizes and counts; later runs print what moved since. Findings the project
accepted (`accept` in the config) are not counted and never fail a run; a critical finding cannot be accepted.
