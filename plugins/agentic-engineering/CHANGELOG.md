# Changelog

- **2.0.1**: The catalog entry names its author, so the plugin list shows who made it instead of an unknown developer.
- **2.0.0**: A new name and eight areas. The plugin is now `agentic-engineering`, the name of the marketplace, and its thirteen areas, which were named like tools, are eight named for a kind of work: `planning` (was but-first-planning), `agents` (the half of agent-works that runs work from the board), `delivery` (agentic-teamwork), `code` (code-diet and codebase-optimizer), `design` (perceptual-loop), `docs` (docs-parity, system-map and picture-this), `writing` (write-like-me) and `harness` (plugin-workbench, context-doctor, workflow-studio, and agent-works' hubs, guard, doctor, setup, memory and decisions). Routes stay one flat level and take plain names: `docs-sync` is `docs sync`, `reuse-first` is `code reuse`, `optimize-codebase` is `code restructure`, `visualize` is `docs figure`, `resource-locks` is `agents locks`, and `docs/plugins.md` lists them all. An agent's addresses are `/agentic-engineering:<area> <route>`, `agentic-engineering:<agent>` and `mcp__agentic-engineering__<tool>`, and a person still types one skill, `/agentic-engineering:start-here`. Nothing in a repo moves: every file an area wrote there keeps its path, and so do the `aw`, `pt` and `pl` commands and the git config keys. Reinstall as `agentic-engineering@agentic-engineering`: install it and open one session before uninstalling `agentcraft`, because uninstalling deletes that plugin's data directory, and each area copies what it kept there into its own folder the first time it runs. `userConfig` values do not carry over, and an `aw` launcher installed earlier needs `setup` run again. The `design` area gains its second half, a web front end held to the person's design system: `system` (which the person starts) records one system for all their projects in their profile, read from its `design-system.json` or described once by interview; `adopt` installs it at a tag and commits `.agents/design.json`, the system's rules as `.agents/rules/design.md`, and a one-file checker, `.agents/scripts/design-check.mjs`; and `check` fixes what that checker finds with the system's own tokens and components. The pin opts a repo in, one critical line sends front-end work there to the rules and the check, and a web front end that is not on the person's system hears once that it could be.
- **1.4.0**: Three changes to how a round of work runs, and shorter READMEs. Inside an orchestrated round, models step down a tier: a child session starts one tier below the orchestrator and never below Opus, its brief tells it to start subagents one tier below itself and never below Sonnet, a judge is never stepped down, and a card can carry a model pin (`aw board add --model`, `aw board grant --model <pin>|step`) that wins over all of it. A plan written in Claude Code's plan mode must end with an `## Orchestration` table (or `Orchestration: none, <why>`) saying what each unit runs as, what it waits on, its files and its model; leaving plan mode is refused up to twice without one, and after approval the session is held to it. After a push, an agent sees a change request's checks watched instead of asking when to look: `ship` ends by running `mr.mjs wait <n> --checks` in the background, except on a GitHub pull request the desktop app already watches, where it does not poll. A card is now built by a subagent unless the person asked for sessions (in words, with Start on the board pane, or by approving a plan whose unit says `session`): a child session costs them approvals and cleanup, so `dispatch`, `orchestrate`, the critical line and the plan format all default to a subagent, recorded with `aw board bind <id> --subagent`. The plugin README is in the standard order and under 800 words.
- **1.3.0**: but-first-planning holds several specs and plans in one repo. Beside the project workspace, `.agents/plan/`, which is untouched, a feature or a long task gets a named one, `.agents/plans/<name>/`: a few spec pages, the plan cut from them, its progress, and no interview or site. `spec-write` makes one itself (`scaffold.mjs --workspace <name>`), `spec-init --plan <name>` does it by hand, and `grill` proposes one when a task outgrows a card. A named workspace holds a launcher where the project holds each script and runs the one copy in `.agents/plans/_scripts/`, so every command reads the same in both; it reads `tracker.md`, postures, glossary and decisions from the project's where it has none. Routes write `P` for the workspace and the area settles which it is before the first read (`--plan <name>`, what is at hand, the only one there is, else ask); the ten workflows take `workspace`. What a named plan publishes says its name (a `plan:<name>` label, `epic::<name>.01-core`, a milestone `<name>.01-01 store`), its issues are `<name>.EE-SS-II` on the agent-works board, and the plan gate, the stale-script briefing and `--refresh` cover every workspace. The gate and the workbench scanner accept a route's name for a directory of the repo it works in.
- **1.2.3**: The stubs are gone. The catalog lists this plugin alone, so the fourteen old plugin names no longer install, and a copy still installed under one no longer updates into this plugin: install `agentcraft` by name, then uninstall the old one. The alias skills three of them kept (`init-project`, `plan-decompose` and `spec-open`, `review`) went with them, so a file copied into a repo that still prints one of those old addresses names nothing now.
- **1.2.2**: Pictures. context-doctor has a figure of a rule lost at a compaction and found in the transcript, and its page screenshot shows the findings card; write-like-me's figure is retaken with the review route named.
- **1.2.1**: The workbench's scanner stops misreading three things. A link written inside a fenced block or a code span is text to copy and is no longer counted as broken (SQ7). An agent a file names by its address, `<plugin>:<name>`, is no longer an orphan, and neither is a file in a `templates/` tree where a file outside the tree names that directory (CS3). A plugin with none of these scores as it did.
- **1.2.0**: plugin-workbench makes both shapes. `create-plugin` proposes one from the interview (plain while a plugin is one body of work and about eight skills or fewer, areas when it holds several, never for reach), and the scaffolder takes `areas` and `entry` in a spec: each area comes out callable and out of the slash menu with its routes listed as `<route> (<cue>)`, a route table, and the compaction line; each route names its directory from its own file; the entry skill names every area. A skill only agents call is `mode: "callable"`. Two new references, `shapes.md` (the rule of thumb, what areas buy and cost, how to move) and `measuring.md` (a reach lane, the baseline, the bar of "no worse", and what to do with a miss). `plugin-scan.mjs --score` takes `--measured <diagnose.json>`, the output of context-doctor's `diagnose --json`, and carries what that session showed beside the score, moving no number; the scorecard shows it as a block of its own, and the listing's size at each window. `improve-plugin` never changes a plugin's shape to raise a score, never runs sessions or a repo's live tests, and reports which of its fixes changed what an agent sees and so are not measured.
- **1.1.0**: context-doctor gains `diagnose`, now its default route. It reads a session transcript for the faults that have a known cause and names each with its level, whose it is, where, and the fix: a hook over the host's 10,000 characters or near it, start context a compaction did not bring back (and whether the hook did not run, ran silent, or failed), a skill call the host refused, a hook that failed, output that reached only the person, the same text on every turn or said twice, critical lines over 7,500 characters, context that came back only on a resume, a route not read again after a compaction, skills listed by name only, a skill called twice in one segment, and a searcher subagent that started with plugin context. `context-lens.mjs diagnose [session] [--json]` prints them; the page `serve` opens shows them as its first card, each opening the event it was raised from. The lens's JSON gains a block's size in characters and what the host said to a refused call.
- **1.0.0**: The twelve plugins became this one. Each is now an area (agent-works, agentic-teamwork, but-first-planning, code-diet, codebase-optimizer, docs-parity, perceptual-loop, picture-this, plugin-workbench, system-map, workflow-studio, write-like-me), and the context lens left plugin-workbench to be a thirteenth, context-doctor. What was a skill is a route: a `ROUTE.md` its area reads by path, never listed, so the skill listing holds fourteen names where it held about eighty. An agent calls an area with the route as the first word of its arguments, `/agentcraft:<area> <route>`; a person types `/agentcraft:start-here`, the only entry in the slash menu, or asks for the work in words. A skill only a person could start is a route its area marks so, and an agent takes it only when the person asked. The twelve old names, and the two before them (marvelous-miro, animated-storytelling), stay as stubs that depend on this plugin, so an update of one brings it in; install `agentcraft` by name as well, so it stays when the stubs go. A sync interval set for the agent-works plugin does not carry over: `syncIntervalSeconds` starts again at its default of 120 seconds, so set it again with `claude plugin configure agentcraft@agentic-engineering`. The conventions agentic-teamwork scaffolds are version 2: the session check a repo tracks offers `agentcraft`, and is satisfied by it or by the agentic-teamwork plugin a machine still runs. `aw doctor --machine` also reports the Claude Code build against 2.1.321 and whether `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set, the two things a stub's update leans on. An area's own `CHANGELOG.md` is its history up to the move and takes no new line. Beyond the move: every area's critical lines print from one session hook and the briefings from a second, so a machine without Node hears so once; write-like-me's hooks say nothing until a profile exists, and its session hook is gone; the agent-works briefing names an `aw` launcher written before the move; plugin-workbench's CS7 asks for one SessionStart command that tells the person Node is missing, where it asked for every one; and a reference file read by path names its directory from its own location, since no plugin variable is filled in for it.
- **0.1.0**: The `start-here` skill, on its own. Typed with no argument it asks which areas a person wants in up to four grouped questions, explains each one chosen, asks how they want to use it, and hands off to the skill that does the work. Given a task, or with nobody to ask, it asks nothing and names the area and skill that fit. The areas are the twelve agentic-engineering plugins, and a hand-off goes to one of their skills by its address; a skill only a person can start is named for them to type.
