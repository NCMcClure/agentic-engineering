# Changelog

- **1.0.0**: Node 22 throughout, no Python. `repo_scan.py` is now `repo-scan.mjs`: the same JSON profile, plus `missing_init` in a Python repo, the same on every machine (names visited in sorted order, forward-slash paths). `verify_source_structure.py` is now `verify-structure.mjs`, and it grades the AGENTS.md hubs too: the hub checker is bundled again (`verify-hubs.mjs`), so hub structure is verified whether or not agent-works is installed. A critical finding (a Python package directory without `__init__.py`, source beside a hub) fails a stage; the rest warn. **Breaking:** (1) the workflows refuse to start without `approved: true`, which the skills set only after you have seen the plan: `optimize-codebase` now shows a run plan and waits, where it used to launch. (2) Workflow arguments: `hubVerifyCommand` is gone, `structVerifier` now points at `verify-structure.mjs`, and the rollup's `hubs` key is `structure` (counts by severity, and what remains). (3) CLAUDE.md twins are no longer a question: a repo with a root `AGENTS.md` and no root `CLAUDE.md` gets none, any other repo gets one beside each new hub, a symlink to `AGENTS.md` (the one line `@AGENTS.md` where a symlink cannot be made); `claudeMd: true|false` overrules. Existing `@AGENTS.md` files are accepted as twins. (4) The organize apply's Verify is stricter: a hub it just wrote that leaves a child unnamed or names a missing path fails the apply. (5) In a sweep, an ORGANIZE round that reds is reverted, where it used to be left uncommitted on the branch. Also: the three skills run without the Workflow tool, and without subagents, under `references/subagent-fallback.md`; the root hub is written from the four rules in `references/agent-hubs.md` (the stub file is gone); the stage detail moved from the README to `docs/how-it-works.md`.
- **0.4.0**: hubs, decision records and the glossary defer to the agent-works plugin, the one owner of how a codebase is set up for agents. **Breaking:** (1) decision records and the glossary move to `.agents/decisions/NNNN-slug.md` and `.agents/CONTEXT.md` (honouring `paths.decisions` / `paths.glossary` of `.agents/agent-works.json`); `docs/adr/` and a root `CONTEXT.md` are no longer read or written — move existing files there. (2) The bundled hub verifier `verify_agents_hubs.py` is gone: the workflows take a `hubVerifyCommand` argument (`"aw hubs"` when the `aw` command exists, replacing the `hubVerifier` path argument) and, when it is empty, still write hubs but report "hub structure not verified: agent-works not installed". Also: `references/agent-hubs.md` and the root stub shrink to the five rules plus the fallback; in a repo with `.agents/agent-works.json` the CLAUDE.md sibling question is not asked (its `claude.twins` setting decides); `CONTEXT-FORMAT.md` and `ADR-FORMAT.md` shrink to the minimal formats; leftover `.gitignore` entries from the plugin's previous home removed.
- **0.3.0**: AGENTS.md progressive-disclosure hubs. The organizer plans and writes orientation hubs on the post-move tree — a new `HubDraft` phase places them (root always, every non-leaf code dir) and drafts honest one-line-per-child Layout sections from the real files; apply writes/merges them (user prose never clobbered) with opt-in `CLAUDE.md` siblings containing `@AGENTS.md` (asked once per repo, detected from the root import thereafter); the Design phase now includes the nesting moves hub isolation requires (no source files beside a hub). New owning contract `references/agent-hubs.md` (philosophy gains principle 9), new `verify_agents_hubs.py` verifier (whole-repo, warn-ramp until a root hub exists, then isolation is critical) gating the organize apply and reported baseline→final by optimize-codebase; the DECOMPOSE/DEEPEN engine prompts carry a hub-currency duty so moved/split files update their governing hub in the same commit. Hubs-only runs (`hubs: "only"`) retrofit hubs onto an already-tidy repo with zero moves.
- **0.2.3**: emitted recon/verify commands resolve `python3` or `python` rather than hardcoding `python3`, matching the existing "python3 or python" availability check so a `python`-only box (e.g. Windows/Git-Bash) doesn't drop to degraded mode.
- **0.2.2**: README reworded.
- **0.2.1**: bundled CONTEXT-FORMAT.md/ADR-FORMAT.md (fixing links that escaped the plugin); always-on description footprint cut from ~574 to ~194 est tokens with distinct triggers per skill; HTML report skeleton ships as an asset; flat-max threshold single-sourced in repo_scan.py; workflow fixes (Measure phase in meta, schema'd recon-scan, real plan path in the verify prompt, soft-judgment panel lenses floored at sonnet).
- **0.2.0**: language-agnostic engine: ecosystem profiles (Python, JS/TS, Go, Rust + `generic` fallback) detected at Setup drive the toolchain commands, shim strategy, seam census, and codemod guidance; host-repo leftovers removed from the defaults; ORGANIZE degrades gracefully when `python3` is absent.
- **0.1.0**: initial release via the agentic-engineering marketplace (plugin renamed from `optimize-codebase` to `codebase-optimizer`; the entry skill keeps its `optimize-codebase` name).
